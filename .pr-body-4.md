## Problem
The extension only ever ingested the first page of GitHub activity events. When users had more than 30 recent events, the older contributions were silently ignored, leaving the pet under-rewarded after hackathons and large coding bursts.

## Root cause
The pagination logic checked whether the next-page value matched the current page instead of advancing beyond it. That prevented the loop from ever moving to page 2 or later, so only the first 30 events were ever considered.

## Fix
- Corrected the next-page detection to advance when the API returns a larger page number.
- Kept iterating through all available `rel="next"` pages up to the GitHub event limit.
- Preserved the cap on total batches without skipping valid later pages.

This ensures large activity histories are fully ingested instead of truncating data after the first page.
