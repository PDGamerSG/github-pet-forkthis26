## Problem
The pet XP could increase repeatedly even when the user had not done any new GitHub work. Each sync reinserted the same GitHub event IDs into the local database, so the same activity was counted over and over.

## Root cause
The database accepted duplicate `event_id` values in `repo_activity`, and the sync path did not guard against repeated event IDs before storing them.

## Fix
- Added a deduplication pass for existing `repo_activity` rows before enforcing uniqueness.
- Enforced a unique `event_id` index on the activity table.
- Switched inserts to `INSERT OR IGNORE` so future syncs skip already-processed events.

This prevents repeated popup syncs from re-awarding XP for the same commit, issue, or pull request event.
