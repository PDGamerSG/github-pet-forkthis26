## Problem
The streak stayed frozen even after multiple days of inactivity. The sync routine compared the last activity to itself when there were no new GitHub events, so the streak never saw the current date and never reset.

## Root cause
When `sync-github` returned zero new events, it passed the previous `pet.last_activity` back into `calculateStreak` instead of the current day. That made the time difference zero and left the streak unchanged.

## Fix
- Added a `comparisonDate` that falls back to the current calendar date whenever no newer activity exists.
- Kept using the newest event date only when a truly newer GitHub event was received.
- Preserved the existing streak logic for active streaks while allowing stale streaks to reset after inactivity.

This means a streak now lapses correctly after the user has been inactive for more than one day.
